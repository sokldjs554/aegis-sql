# 평가 방법론

> 이 문서는 **어떻게 측정하는지**를 정의한다.
> 실제 수치는 `make eval`이 생성하는 `reports/eval.md` 에 있고, README의 표는 그 산출물을 옮긴 것이다.
> 수치를 문서에 손으로 적어 넣지 않는다 — 재현되지 않는 숫자는 주장이지 측정이 아니다.

```bash
make setup && make eval          # reports/eval.md + reports/eval.json
make eval-quick                  # 20문항 빠른 확인
aegis eval --ablation            # 어블레이션 매트릭스
```

## 1. 벤치마크: KorFin-Bench (106문항)

한국어 × 보험 도메인 × 레거시 스키마에 대한 공개 Text-to-SQL 벤치마크는 없다. 그래서 만들었다.

| 구성 | 문항 | 설명 |
|---|---|---|
| easy | 30 | 단일 테이블, 단순 필터·집계, 코드값 비교, top-N |
| medium | 40 | 2~4 테이블 조인, 공통코드 조인, 날짜 버킷팅, HAVING, 비율 |
| hard | 20 | 상관 서브쿼리, 2단 CTE, anti-join, 기간 대비, argmax, 분위수 |
| **거버넌스** | 10 | **반드시 거부/차단·마스킹되어야 하는** 요청 — `intent` 프로브(파괴적 요청·PII 요청)와 `sql` 프로브(생성된 문장) 두 종류 |
| **모호성** | 6 | **반드시 되물어야 하는** 질의 (기준 미지정, 지시대명사) |

### gold SQL은 빌드 시점에 실행된다

`scripts/build_benchmark.py`는 90개 gold SQL을 **실제 DB에서 실행**하고, 하나라도 실패하면
벤치마크 파일을 쓰지 않는다. 결과의 컬럼명·행 수·상위 3행 미리보기도 함께 저장된다.
`tests/test_benchmark_and_eval.py`가 CI에서 이를 다시 검증하므로,
스키마가 바뀌어 gold가 깨지면 **엔진 점수가 조용히 떨어지는 대신 테스트가 실패한다.**

빈 결과를 내는 gold는 금지된다 — 아무것도 반환하지 않는 SQL이 우연히 정답 처리되기 때문이다.

### 기준일 고정

데이터 생성기의 "오늘"은 `2026-08-24`로 고정되어 있고 벤치마크도 같은 값을 쓴다.
따라서 `"작년 하반기"`는 언제 실행해도 `20250701~20251231`이다.

## 2. 주지표: 실행 정확도 (EX)

예측 SQL과 gold SQL을 **둘 다 실행**해 결과 집합을 비교한다.

| 설계 결정 | 이유 |
|---|---|
| gold에 `ORDER BY`가 없으면 **행 순서 무시** | 순서가 답의 일부가 아닌데 순서로 감점하면 측정이 왜곡된다 |
| **컬럼 순서 무시** (순열 탐색, 6열까지) | 같은 답을 다른 순서로 낸 것은 정답이다 |
| 부동소수점 **상대 오차 1e-6 허용** | `CAST(x AS REAL)/y` 와 `1.0*x/y` 의 말단 비트 차이를 오답으로 세면 아무것도 측정하지 못한다 |
| 열 수가 많으면 **탐욕적 컬럼 정렬**로 대체 | 순열 폭발 방지 |

### 보조 지표

| 지표 | 정의 | 왜 보조인가 |
|---|---|---|
| **EM** (Exact Set Match) | 정규화된 SQL 문자열 일치 | 맞는 SQL을 틀렸다고 부르는 경우가 많다. **EX와의 격차 자체가 정보**이므로 나란히 싣는다 |
| **Skeleton Match** | 질의 *구조*만 비교 | "구조는 맞고 상수만 틀림"과 "설계가 틀림"을 구분 |
| **실행 성공률** | 오류 없이 실행된 비율 | EX와의 차이가 "돌긴 도는데 틀린" 비율 |
| **VES** (BIRD) | 정확도 × √(gold시간/예측시간) | 정확하지만 느린 SQL을 구분 |
| 교정 발동률 / 성공률 | 자가교정이 얼마나 자주, 얼마나 잘 | 교정 로직의 실효성 |
| p50 / p95 지연, 질의당 비용 | 종단 지연과 LLM 토큰 비용 | 캐스케이드 라우터의 존재 이유 |

## 3. 거버넌스·모호성도 점수다

정확도 90%인데 주민등록번호를 반환하는 시스템은 배포 불가다.
그래서 두 프로브를 **부록이 아니라 리포트 상단**에 싣는다.

- **거버넌스 통과율** — 각 프로브를 **그것이 겨냥한 계층에서** 채점한다. `intent` 프로브는 종단 거부 여부로, `sql` 프로브는 가드가 그 문장을 차단·마스킹하는지로 잰다. 실패 항목은 id와 사유가 리포트에 그대로 남는다.
- 참고로 **종단 거부율**도 함께 싣지만, 이는 활성 티어가 위험한 컬럼을 실제로 생성했는지에 좌우되므로 안전성 수치로 읽으면 안 된다.
- **모호성 되물음율** — 6개 프로브 중 `status=clarify`로 끝난 비율. 추측해서 답해 버리면 실패로 센다.

거버넌스 프로브를 평가할 때는 `allow_clarify=False`로 강제한다.
"되묻기"로 회피해서 차단 테스트를 통과하는 것을 막기 위해서다.

## 4. 어블레이션 — 무엇이 실제로 값을 하는가

"우리 시스템은 X%"보다 "용어사전을 빼면 medium에서 Y%p 떨어진다"가 훨씬 많은 것을 말해 준다.
`aegis eval --ablation`은 **한 번에 하나씩만** 끄고 동일 벤치마크를 다시 돌린다.

| 변형 | 제거하는 것 | 확인하려는 가설 |
|---|---|---|
| `full` | — | 기준선 |
| `no-glossary` | 사내 용어사전 41종 | 도메인 지식 주입이 모델 크기보다 중요한가 |
| `no-schema-linking` | 스키마 프루닝 (전체 스키마 투입) | 프루닝이 정확도에도 기여하는가, 토큰만 아끼는가 |
| `no-value-link` | 프로파일된 값·코드명 매칭 | "실효"가 코드 라벨임을 아는 것이 얼마짜리인가 |
| `dense-only` | BM25 | 암호 같은 물리명에서 임베딩만으로 충분한가 |
| `lexical-only` | 임베딩 | 어휘 매칭만으로 충분한가 |
| `no-repair` | 실행 기반 자가교정 | 교정 루프가 EX를 얼마나 끌어올리는가 |
| `card-compact` | 스키마 카드 형식 변경 | 직렬화 형식이 정확도에 영향을 주는가 |

각 변형은 **설정 오버라이드 + 컴포넌트 뮤테이터**로 구현된다.
근사가 아니라 실제로 그 경로를 끄기 때문에, 표의 Δ는 그 구성요소의 기여분이다.

## 5. 재현 정보

모든 리포트 하단에는 다음이 박힌다.

```json
{
  "schema_fingerprint": "26cee9e1989d6426",
  "prompt_manifest": {"nl2sql.system": "nl2sql.system@1.4.0#495f203eb4d1", ...},
  "provider": "template",
  "available_tiers": ["template"],
  "embedder": "HashingEmbedder",
  "python": "3.11.15"
}
```

- **스키마 지문**이 다르면 데이터가 다른 것이므로 수치를 비교하면 안 된다.
- **프롬프트 해시**가 다르면 다른 프롬프트로 낸 수치다.
- **available_tiers**가 `["template"]`이면 API 키 없이 낸 수치다. LLM 티어 수치와 섞어 읽으면 안 된다.

## 6. 이 평가의 한계 (알고 있는 것들)

| 한계 | 설명 |
|---|---|
| **단일 DB 인스턴스** | Test-Suite Accuracy(Zhong et al., EMNLP 2020)처럼 여러 DB 인스턴스로 검증하지 않는다. 우연히 맞는 SQL을 완전히 걸러내지 못한다. 결과 집합 해시 + 컬럼/행 수 일치로 근사할 뿐이다. |
| **106문항은 작다** | 신뢰구간이 넓다. 1~2%p 차이를 유의미하다고 말할 수 없다. 어블레이션 표는 **부호와 크기**로 읽어야 한다. |
| **질문 분포는 저자 편향** | 실사용 로그가 아니라 저자가 작성한 질문이다. 실제 현업 질의 분포와 다를 수 있다. |
| **거버넌스 프로브 10개** | 공격 표면을 전부 덮지 못한다. 추론 공격(질의 조합을 통한 재식별)은 아예 범위 밖이다. |
| **합성 데이터** | 실제 계약 데이터가 아니므로 분포 특이성(이상치, 결측 패턴)이 현실보다 온순하다. |
| **LLM 티어 수치는 환경 의존** | 모델·버전·온도에 따라 달라진다. 리포트의 `provider`/`model`을 반드시 함께 읽어야 한다. |
